Component Parameters

Parameter Type Default Description
buttons list [] List of button configurations (dicts with 'text', 'active', 'disabled' keys or strings)
mode string "one" Selection mode ("one" for single selection, "multi" for multiple selection)
targets string "button" Selector for elements that should behave as buttons in the group
cls_active string "" Additional CSS class to apply to active buttons
required_button boolean False Whether at least one button must be active
onButtonClick function Metro.noop Event handler triggered when a button is clicked
onButtonGroupCreate function Metro.noop Event handler triggered when the button group is created
cls_button_group string "" Additional CSS class for the button group container

Button Configuration Structure

Key Type Required Description
text string Yes Display text for the button
active boolean No Whether the button is initially active
disabled boolean No Whether the button is disabled
attrs dict No Additional HTML attributes for the button

CSS Variables

Variable Default (Light) Dark Mode Description

Global Configuration

You can set global defaults for all Button Group components:

Metro.buttonGroupSetup({
    clsActive: "highlighted",
    mode: Metro.groupMode.MULTI
});

HTML Structure

<div class="button-group" data-role="button-group" data-mode="one" data-targets="button">
    <button>Option 1</button>
    <button class="active">Option 2</button>
    <button>Option 3</button>
</div>

Where:

  • data-role="button-group" - Identifies the element as a button group component
  • data-mode - Selection mode ("one" for single, "multi" for multiple)
  • data-targets - Selector for button elements (default: "button")
  • data-cls-active - Custom active class (optional)
  • data-required-button - Whether at least one button must be active
  • data-on-button-click - Click event handler (optional)
  • data-on-button-group-create - Creation event handler (optional)

Accessibility

  • Use semantic button elements when possible for proper keyboard and screen reader support
  • Ensure there is sufficient color contrast between active and inactive states
  • Consider adding ARIA attributes to clarify the role and state of the button group

Best Practices

  • Use button groups for related options where users need to make a selection
  • Clearly indicate the active state with visual cues
  • For single-selection mode, consider making one option selected by default
  • Keep the number of options in a button group reasonable (typically 2-5)
  • Use consistent styling for button groups throughout your application
